# Selected-Portfolio Socket.IO connection on the Equipped listener

The Server Consumer establishes one browser-owned Socket.IO connection on Equipped Fastify's existing public listener and `/socket.io` path. The browser client uses its current origin, WebSocket-only transport, credentialed cookie handling, and no token, Selection id, query, or Socket.IO auth payload, so the upgrade carries the same `gorchestra_session` and `gorchestra_selection` cookies as REST without exposing the HttpOnly Session token to client code. This same-origin client policy does not add Server-side origin rejection; Equipped continues to accept the physical transport connection when socket authentication fails.

REST and Equipped socket authentication share one transport-neutral selected-Portfolio access resolver. It verifies the cache-confirmed Session first, then verifies the Selection Cookie and re-reads the current User, Workspace, Active Workspace Membership, Portfolio Registry Entry, and Active Workspace Owner role. Equipped receives only a minimal `{ id, sessionId, workspaceId, portfolioId, workspaceMemberId }` socket identity when those checks pass and `null` otherwise. That identity is a connection-time routing snapshot, not continuing authority: every future registered socket path must authorize the concrete operation and re-resolve current Session, Selection, membership, and Portfolio access instead of trusting the snapshot or Agent Run id alone.

Selected routes retain REST-only authorization during SSR. In the browser, route entry additionally requires Socket.IO transport readiness within ten seconds; successful Session refresh and Portfolio Selection replacement force and await a new connection, while logout, Selection clear, and browser auth/Selection-loss boundaries disconnect first. A failed REST credential-removal operation attempts to restore the still-valid prior connection, and a later network disconnect leaves the selected UI mounted while Socket.IO reconnects. Socket.IO owns ingress closure during Server shutdown so upgraded clients and the attached HTTP listener close deterministically before infrastructure teardown.

We chose this connection-only slice to validate one authenticated transport boundary before introducing application rooms. It adds no production socket path, Agent Run Channel, Notification delivery, replay, retention, subscriber queue, presence state, connection UI, per-connection logs, or cross-tab revocation coordination; those concerns remain deferred to the Agent Run Channel slice, where Equipped's path registration and explicit denial/routing semantics must be decided from the concrete subscription contract.
