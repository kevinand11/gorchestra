# Cache-confirmed JWT Sessions

The Server Consumer uses a signed JWT cookie for Sessions, containing the User id and normalized email label, and confirms validity through cache entries keyed by User. V1 permits one active Session per User: sign-in stores the current JWT in cache, authenticated requests verify both the JWT signature and cache match, rolling refresh replaces the cached JWT when less than half of the seven-day lifetime remains, and the immediately previous JWT remains valid for a 30-second grace window to avoid concurrent-request failures. We chose this Stranerd-style cache-confirmed JWT cookie approach over opaque durable Session records so Session expiry and cleanup follow cache TTL while still allowing server-side invalidation.
