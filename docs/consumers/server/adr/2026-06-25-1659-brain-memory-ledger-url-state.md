# Brain Memory Ledger URL state

The Brain Memory Ledger uses `/brain/memories` for the filterable Portfolio Memory list and `/brain/memories/:memoryId` for Memory Detail. Ledger filters are represented in URL query parameters and preserved even when supplied values equal defaults, so reloading or sharing the Ledger URL restores the same filtered view without the browser silently canonicalizing state away. Omitted filters use the Server Consumer defaults. Opening a Memory uses a canonical detail URL without carrying Ledger filter query parameters; browser Back preserves the prior filtered Ledger history entry when navigation originated from the Ledger, while deep-linked Memory Detail pages remain clean and stable. Filter Apply writes all filter parameters and uses route push so browser Back restores prior filter states.
