# Brain Memory Ledger URL state

The Brain Memory Ledger uses the `/brain/memories` page with an in-page selected Memory panel rather than a first-slice Memory detail route. The selected Memory id and supplied Ledger filters are represented in URL query parameters and preserved even when supplied values equal defaults, so reloading or sharing the URL restores the same selected Ledger view without the browser silently canonicalizing state away. Omitted filters use the Server Consumer defaults. In the first client slice, the selected panel resolves the selected Memory from the loaded Ledger rows rather than issuing a separate detail read; the Portfolio-level Memory detail API may still exist for later use. Row selection updates the selected Memory query parameter with route replacement so exploratory selection does not flood browser history, while filter Apply writes all filter parameters and uses route push so browser Back restores prior filter states.
