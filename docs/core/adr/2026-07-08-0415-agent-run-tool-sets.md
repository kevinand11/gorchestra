# Agent Run Tool Sets

Core stores an immutable `toolSet` snapshot on each Agent Run, with compact `{ name, contractVersion }` entries resolved at Model Agent Run creation alongside source runtime setup. Tool Set derivation is Core-owned from Agent Run Purpose and Project Source Type: Planning and Revision Planning get read-only workspace exploration tools plus their proposal tool, while Execution and Revision Execution get workspace exploration, the `sh` command tool, and file mutation tools. Agent Run Profiles do not configure tools in v1, and unsupported snapshot entries fail explicitly rather than being silently dropped.

Gorchestra's built-in workspace tools are heavily inspired by Pi but adapted to Core's sandbox boundary. The catalog uses `read`, `grep`, `find`, `ls`, `sh`, `edit`, and `write`: `read`, `ls`, `edit`, and `write` use managed sandbox file APIs; `grep` and `find` are command-backed through required `rg` and `fd`; and the shell tool is named `sh` because Core requires POSIX `sh` rather than a Bash binary. Global runtime requirements are stored at the front of source runtime requirements and always run in Agent Run Profile Preflight; in v1 they verify root-runnable `sh` and ensure `rg`/`fd` with best-effort package-manager installation before source-specific setup such as Git and repository checkout.

Managed Sandbox Providers own the Core-facing safety boundary for these tools: raw providers remain generic, managed file APIs deny Core-internal paths such as `/workspace/.gorchestra/**`, initialize the protected internal directory for non-root model command isolation, expose byte-capable file read/write plus directory listing and recursive Core cleanup `deletePath` for files or directories, and expose managed text redaction that reads the prepared sandbox runtime environment store before persisted tool-call inputs or tool outputs are recorded. Tool outputs are bounded and Pi-like: search/list/read outputs use Pi-inspired limits, `sh` persists structured redacted command evidence with per-stream truncation, `edit` persists redacted diff evidence, and `write` persists concise confirmation rather than duplicating its input. Tool execution is serialized by mutation capability: read-only tools may run together, `edit`/`write` queue by file, and `sh` acts as a global filesystem mutation barrier.
