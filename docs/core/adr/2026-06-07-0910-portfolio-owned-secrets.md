# Portfolio-owned Secrets

Gorchestra Secrets are owned by a Portfolio, and Secret Bindings may resolve from Portfolio to Project to Delivery. Secret protection is the responsibility of the consuming layer: a server app may encrypt stored Secret values and decrypt them before passing resolved runtime values to the core engine, while another consumer might use a different protection mechanism. The core treats plaintext Secret values as transient runtime input and must not expose, log, or persist them. This supersedes the earlier Workspace-owned, Project-level-first binding model: Portfolio ownership keeps reusable Secrets inside the orchestration boundary while avoiding accidental exposure across unrelated Portfolios in the same Workspace.
