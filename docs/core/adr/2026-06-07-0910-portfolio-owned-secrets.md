# Portfolio-owned Secrets

Gorchestra Secrets are named sensitive values owned by a Portfolio, and Secret Bindings may resolve from Portfolio to Project to Delivery for Agent Run environments. V1 Secrets do not have provider-specific Secret types; provider configs and bindings reference Secrets by ID, and the Secret name identifies its purpose to users. Secret protection is the responsibility of the consuming layer: a server app may encrypt stored Secret values and provide plaintext through a Core Service, while another consumer might use a different protection mechanism. Core decides which Secrets are needed for Core-owned provider behavior, treats plaintext Secret values as transient runtime input, and must not expose, log, or persist them. Referencing a Secret from provider config does not expose it to Agent Runs; Agent Run exposure requires an explicit Secret Binding. This supersedes the earlier Workspace-owned, Project-level-first binding model: Portfolio ownership keeps reusable Secrets inside the orchestration boundary while avoiding accidental exposure across unrelated Portfolios in the same Workspace.
