# Atomic Plan Output acceptance

Planning Agent Runs produce Plan Outputs as structured proposal shapes containing proposed new Deliveries with their initial Slices, plus Memories and Links, rather than directly mutating authoritative Portfolio graph state. A Plan Output is not itself a stored Portfolio artifact. A Plan Output does not add Slices to an existing Delivery; follow-on work is represented as a new Delivery that may depend on an existing Delivery or another proposed Delivery in the same Plan Output through a `depends-on` Link. Slice-level ordering is represented with Slice-to-Slice `depends-on` Links only within the same Delivery. A Plan Output is accepted or rejected as a whole: accepting it materializes all proposed artifacts atomically, including Instruction Sources stored on the materialized Slices, while rejecting it materializes none of them. If only part of the output is acceptable, the Planner negotiates with the intelligence behind the Agent Run until a new acceptable whole is produced. The Plan remains reusable and may produce more Plan Outputs later.
