# Atomic Plan Output acceptance

Planning Missions produce Plan Outputs containing proposed new Deliveries with their initial Slices, plus Memories and Links, rather than directly mutating authoritative Portfolio graph state. A Plan Output does not add Slices to an existing Delivery; follow-on work is represented as a new Delivery that may depend on an existing Delivery through a `depends-on` Link. Slice-level ordering is represented with Slice-to-Slice `depends-on` Links only within the same Delivery. A Plan Output is accepted or rejected as a whole: accepting it materializes all proposed artifacts atomically, while rejecting it materializes none of them. Rejected Plan Outputs remain in Planning history for auditability and context, but their proposed artifacts do not become authoritative Portfolio graph state. If only part of the output is acceptable, the Planner negotiates with the intelligence behind the Mission until a new acceptable whole is produced. The Plan remains reusable and may produce more Plan Outputs later.
