# Opaque operation attribution

Gorchestra core records attribution using Audit Stamps on attribution-bearing records and outcomes. Consumers authorize operations before calling core and pass an Operation Context containing a Local Actor Ref and optional correlation ID; core stores those values opaquely and never interprets server, workspace, user, or CLI identity semantics. A Local Actor Ref contains only a consumer-defined actor type and actor id. During restore, local Audit Stamps from the restored Snapshot become imported Audit Stamps that preserve the original operation time while marking attribution as not locally resolvable. This lets multi-user consumers answer questions such as who created a Project, accepted work, opened a Revision Gate, or closed a Delivery while keeping server-specific identity models out of core.
