# AI SDK-backed Model Provider Protocols and Agent Run transcript cursors

Superseded in part by [Agent Run Profiles and Project-scoped Delivery work config](./2026-07-04-1328-agent-run-profiles-and-delivery-work-config.md), which makes Agent Run profile snapshots and audited Agent Run Model Use Overrides authoritative instead of initial model-selection transcript events.

Core Model Provider Protocol implementations use Vercel AI SDK as the language-model execution boundary for every model-backed interaction. Concrete protocol adapters resolve a stored Core Model Provider, Model, and resolved transient Secret access into an AI SDK `LanguageModel` plus any non-thinking provider-specific `providerOptions`; the Agent Run runtime and Model Preflight then call AI SDK `streamText`. Agent Run thinking control uses AI SDK's generic `reasoning` option after Core validates provider-protocol support. Consumers still do not provide Model Provider Protocol implementations, and Core continues to own Model Agent behavior, tool contracts, transcript persistence, provider error classification, and safe validation boundaries.

Supported v1 Model Provider Protocols are `openai-responses`, `anthropic-messages`, and `google-generative-ai`. We dropped `openai-completions` with no legacy compatibility because it is legacy prompt/completions-shaped behavior that does not fit Gorchestra's message/tool/thinking Agent Run model. Existing pre-v1 records that use `openai-completions` are invalid and should be recreated with a supported protocol.

Model Preflight remains observational and non-lifecycle, but it now proves model-backed reachability with a tiny bounded AI SDK `streamText` generation probe rather than provider metadata retrieval. Preflight uses the same language-model resolution path as Agent Runs, does not create Agent Run Events, uses no tools, validates configured positive thinking support as Core metadata, and sends no AI SDK reasoning option in the generation probe. Provider and AI SDK failures are mapped to safe Validation Evidence reasons such as authentication failure, access denied, model not found, rate limited, content filtered, provider unavailable, or generation failed.

One Core Agent Run turn is one AI SDK `streamText` multi-step operation. AI SDK owns the internal model/tool loop and may execute multiple tools in the order or concurrency it chooses within Core's bounded step limit. Core does not retain its former `exclusive`/`parallel-safe` tool scheduling concept. Core still validates tool inputs with Core pipes, executes only Core-approved tools, records safe tool outputs, and persists the Core-shaped audit transcript. Each AI SDK language-model call within the turn becomes its own `model-message-started` / `model-message-ended` pair under the same `turn-started`; model outcomes use `tool-calls` when the step contains one or more tool calls. Tool calls are recorded as `tool-call-started` / `tool-call-ended`; there is no separate `tool-call-scheduled` event.

Agent Run Event ordering uses a Core-owned monotonic ULID cursor instead of an auto-incrementing sequence. `AgentRunEvent` keeps its storage `id` for public command inputs and stable storage identity, while `cursor` is the transcript ordering, pagination, and intra-transcript reference value. Public commands continue to accept event ids; stored Agent Run Event bodies reference other Agent Run Events by cursor. Queries page with `afterCursor`, `turn-started` records `contextThroughCursor`, compaction records `firstKeptCursor`, and live model/tool update events reference started-event cursors. Core runtime values expose a validated `nextCursor` generated with a monotonic ULID factory.

Model Thinking Level semantics use `none` for an explicit best-effort request to disable thinking for the Agent Run. `null` runtime thinking means Core sends no AI SDK reasoning option. Positive levels are configured on the Model as `capabilities.thinking.supportedLevels`, while `none` is implicit and always selectable. Core validates configured positive levels against the Model Provider Protocol before they become selectable or runnable; unsupported mappings fail as `model-thinking-level-unavailable` rather than silently downgrading. Agent Runs pass selected thinking through AI SDK's generic `reasoning` option (`none`, `minimal`, `low`, `medium`, `high`, or `xhigh`) instead of storing provider-value strings or building provider-specific thinking options.

## Consequences

- `@gorchestra/core` depends directly on `ai`, AI SDK provider packages, and `ulid`; direct model SDK dependencies are removed when no longer used.
- Provider-specific protocol files become thin AI SDK language-model resolvers; shared Agent Run runtime owns `streamText`, generic AI SDK reasoning selection, tool wrapping, transcript event persistence, live deltas, and safe outcome mapping.
- Core transcript replay remains independent of AI SDK raw event objects while preserving AI SDK/provider correlation values such as tool call ids and nullable AI SDK call ids.
- Turn-level failures before a model/tool-specific outcome can be recorded are represented by `turn-ended.outcome`; storage and invalid Core Service output failures remain operation Result errors rather than transcript facts.
- Model Preflight may incur a minimal generation cost because AI SDK does not provide a provider-agnostic model metadata existence check.
