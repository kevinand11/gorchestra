# Agent Run Runtime Requirements and Sandbox Preparation

Agent Runs use Core-owned Agent Run Runtime Requirements and idempotent Agent Run Sandbox Preparation rather than Consumer-defined sandbox semantics. Core stores normalized ordered runtime requirements on Agent Run Profiles and Agent Run Profile Snapshots, stores static Project Source or Agent Run Purpose runtime requirement contributions separately on Agent Runs, materializes accepted runtime requirement override batches on Agent Runs, and prepares sandboxes through separate dispatch work before model turns. V1 runtime requirement variants are Environment Secret Requirements and Run Command Requirements; a separate dependency requirement/catalog abstraction is deferred until repeated command patterns justify it. Dynamic source-control checkout commands are generated during Sandbox Preparation after provider ref resolution, while Repository access Secrets remain typed transient inputs for checkout commands and are not persisted into the Agent Run runtime environment by default. Runtime requirements are applied in order: source/purpose-contributed requirements run first, profile snapshot requirements run second, override batches run in event order, Environment Secret Requirements compile to Core-authored sandbox commands, Run Command Requirements let users provide custom sandbox preparation commands, repeated environment Secret assignments use last-write-wins, and exact duplicate requirements are rejected as redundant.

Agent Run Sandboxes remain deployment-local runtime state and Portfolio Snapshots do not make sandbox contents portable. [Agent Run Sandbox Config and Runtimes](./2026-07-06-1900-agent-run-sandbox-config-and-runtimes.md) supersedes the original opaque sandbox assignment boundary with explicit Agent Run Sandbox Config, Agent Run Sandbox Keys, and config-resolved Sandbox Runtimes. Core still resolves source-control checkout specs, Repository access Secrets, and environment Secrets just-in-time and translates checkout and environment preparation into explicit sandbox commands. User-authored Run Command Requirements use required-label structured argv command shapes with arbitrary executable names and the same generic sandbox command execution primitive, avoid raw shell strings and shell operators in v1, execute inside sandbox paths, load the prepared sandbox runtime environment store, and remain distinct from Agent Run model tools and transcript tool calls. Run Command Requirements and future runtime requirement variants may carry `commandSecretEnv` records from environment variable name to Secret id that resolve Secret plaintext as command-scoped environment variables for that requirement's command execution only. Secret plaintext travels only through typed transient secret input fields such as `commandSecretEnv`, never through command arguments or stored command evidence.

V1 Agent Run Dispatch Requests use separate top-level request types for model turns, sandbox preparation, and sandbox release so the Server Consumer can route to the correct Core Work Operation while coordinating all three with an exclusive Agent Run Dispatch Coordination Claim. New Agent Runs and accepted runtime overrides become Blocked Agent Runs with `sandbox-preparation-pending`; preparation clears the block only after sandbox creation, source checkout, and ordered runtime requirements are ready. Completion of any Agent Run enqueues idempotent sandbox release/wipe, recording sanitized release history while leaving completed runs completed even if cleanup fails.

This supersedes the Secret Binding-based Agent Run exposure detail in [Portfolio-owned Secrets](./2026-06-07-0910-portfolio-owned-secrets.md) and extends [Isolated Agent Run Sandboxes](./2026-06-07-1100-isolated-agent-run-sandboxes.md) with runtime requirement, preparation, and cleanup semantics.
