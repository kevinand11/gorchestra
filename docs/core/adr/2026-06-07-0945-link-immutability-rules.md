# Link type boundary

Gorchestra restricts Core Links to `produced` provenance and `depends-on` execution dependencies. Both are immutable Core facts. Memory-authored references, support, contradiction, and supersession are expressed inside Memory Revision bodies as Memory Inline Links rather than as Core Link types. Memory and Memory Revision are both Portfolio Graph nodes: Memory is the stable note identity, while Memory Revision is the exact content snapshot for provenance. Accepting a Plan Output records produced Links from the Plan to each newly created Memory and to every Memory Revision the Plan materializes, while Delivery and Slice dependencies materialize as depends-on Links. We chose this narrower boundary so Core Links remain workflow/provenance facts, while authored semantic relationships stay editable through Memory Revision history instead of becoming separate archivable graph edges.
