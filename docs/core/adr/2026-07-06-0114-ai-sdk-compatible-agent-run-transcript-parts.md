# AI SDK-compatible Agent Run transcript parts

Core keeps Model Agent as the v1 Agent Type and does not adopt AI SDK `HarnessAgent` as the primary runtime boundary. `HarnessAgent` is for driving external/native agent runtimes with their own sessions, sandbox lifecycle, built-in tools, and resume state; Gorchestra's Model Agent needs to remain a Core-owned, programmatically hosted runtime that resolves Core Models into AI SDK language models, owns Core tool contracts, and records Core Agent Run history.

Agent Run Events will separate Core-recognized runtime/domain facts from durable transcript content. Core facts such as sandbox preparation and release, model-use overrides, runtime-requirement overrides, interrupts, turn boundaries, proposal creation/review, and compaction boundaries remain first-class Agent Run Events. Low-level durable `model-message-started` / `model-message-ended` and `tool-call-started` / `tool-call-ended` choreography is replaced by durable transcript event variants: `input-message`, `assistant-message`, and `tool-message`.

`input-message`, `assistant-message`, and `tool-message` infer their transcript role from the event variant rather than storing a generic nested message role. `input-message` records operator/runtime input parts and has no `turnStartedCursor`. `assistant-message` records finalized AI SDK model output for one model call inside a turn, with required `turnStartedCursor`, resolved model generation facts (`modelId`, `thinkingLevel`, `modelProviderId`, `providerProtocol`, and `providerModelId`), AI SDK-aligned `finishReason`, AI SDK language-model usage with `undefined` normalized to `null` and `raw` plus derived `totalTokens` omitted, Core-computed nullable `cost` as micro-USD component values without a stored total, `responseId`, and ordered AI SDK-supported parts. `tool-message` records Core-executed tool responses for one assistant message, with required `turnStartedCursor`, required `respondsToAssistantMessageCursor`, a source of `tool-execution` or `runtime-recovery`, and non-empty parts.

Agent Run transcript parts use AI SDK-supported part names and shapes where practical, with a required generic `metadata: JsonObject | null` on every part. Core does not invent a separate provider-continuity part; provider-specific continuity values are preserved as metadata on the owning AI SDK part. Assistant `reasoning` and `reasoning-file` parts are persisted in original order for user history, hidden behind disclosure in normal UI, and excluded from future context projection and compaction. Assistant `source`, `file`, and `custom` parts are persisted but not projected by default. Provider-executed tool calls/results/errors are preserved in assistant parts and can project according to AI SDK rules; Core-executed tool results/errors are recorded only in `tool-message` parts with `providerExecuted: false`, Core `started`/`completed` timing, explicit Core `truncation`, and classified `reason` on `tool-error`.

Tool result/error output stored in `tool-message` is the output projected back to the model; Core does not keep hidden full output for context rebuild. When truncation occurs, projection may include a truncation notice derived from the explicit truncation metadata, but the stored output remains the source of truth. If recovery finds an assistant message with unresolved Core-executed tool calls, Core appends a recovery `tool-message` containing synthetic `tool-error` parts with reason `result-not-recorded-before-recovery`, using the recovery time for both `started` and `completed`, before ending the turn or starting another model call.

`turn-started` keeps a non-null `contextThroughCursor` and its reason is limited to a non-empty array of triggering `input-message` cursors; retry reasons are deferred until retry behavior exists. `turn-ended` closes a turn after transcript/tool repair is complete and has only `completed` or `error` outcomes; abort causes collapse into error reasons, and no rendered summary is stored because UI summaries are derived from structured reasons. Context compaction records `compactedThroughCursor` and non-empty `replacementParts` instead of `firstKeptCursor`; compaction replaces only context-projectable transcript content through that cursor and preserves original events for audit. Proposal review events store non-empty system `projectedParts` so the exact model-visible review text is durable, while proposal creation events remain structured Core facts referencing `assistantMessageCursor` plus `toolCallId`.
