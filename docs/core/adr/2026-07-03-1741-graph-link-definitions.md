# Graph Link Definitions and enriched node refs

Core Links use an immutable Link Definition that groups the relationship type with its `from` and `to` Graph Node Refs as one graph fact. Graph Node Refs are self-contained validated addresses: Plans and Deliveries carry Project context, Slices carry Delivery and Project context, and Memory Revisions carry Memory context; Project itself is graph address context rather than a v1 graph node. V1 Link Definitions are limited to `produced` Plan→Memory, `produced` Plan→Memory Revision, `depends-on` Delivery→Delivery within one Project, and `depends-on` Slice→Slice within one Delivery; Links are immutable and non-removable, so they do not carry Archive Periods. We chose this over generic top-level `type`/`from`/`to` fields and archivable Links so storage validation can treat each supported relationship as an atomic definition, execution dependency queries can rely on enriched endpoint context, and provenance/dependency facts cannot be silently rewritten or removed.
