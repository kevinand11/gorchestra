# Consumer-routed Agent Run Notifications

Core publishes flattened `Domain.Notifications.Notification` values through the optional `CoreServices.notifications` service after successful live Agent Run and Agent Run Event writes commit, and publishes safe non-persisted model/tool updates through the same boundary. Consumers own subscription authorization, Agent Run-scoped routing, and transports such as WebSocket channels; notification publication is best-effort, does not block or fail Core work, assigns a sortable non-persisted id at publication time without providing replay, and excludes whole-Portfolio Snapshot restore. Durable Agent Run and Agent Run Event reads remain the recovery source of truth. We chose this over Core-owned listener lifecycle, synchronous required delivery, and a transactional outbox because separate Core instances must share Consumer routing while UI freshness does not justify coupling orchestration success to notification infrastructure or adding durable delivery state.
