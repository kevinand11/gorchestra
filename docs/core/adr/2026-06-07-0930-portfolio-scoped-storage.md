# Portfolio-scoped storage

Each Gorchestra Portfolio has its own storage boundary, such as its own database or file-storage namespace, and Portfolio data IDs are only required to be unique within that boundary. The Workspace/global registry owns Portfolio display metadata and storage location; Portfolio storage does not own name or description. Export creates a passphrase-encrypted Portfolio Snapshot from the currently-open Portfolio storage contents, and Restore atomically replaces all currently-open Portfolio storage contents with a Snapshot while preserving exported IDs. Creating a new Portfolio from a Snapshot is a consumer workflow: the consumer provisions and registers a new empty Portfolio storage boundary, opens Core for that Portfolio, then restores the Snapshot into it. We chose isolated Portfolio storage over one shared portfolio table space because it simplifies full-fidelity Snapshot export/restore and reduces accidental cross-Portfolio coupling.
