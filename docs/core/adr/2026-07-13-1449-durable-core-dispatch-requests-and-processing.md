# Durable Core Dispatch Requests and Core-owned processing

This supersedes the in-memory Consumer `request`/`ready` marker lifecycle and temporary Delivery Work Dispatch Action portions of [Dispatch coordination claims and Delivery work scheduling](./2026-07-04-2022-dispatch-coordination-claims-and-delivery-work.md). It retains typed hierarchical Dispatch Coordination Claims, parent/descendant exclusion, shared Slice capacity, and the split between Delivery Work Scheduler Passes and concrete Delivery Work Operations.

Core stores each logical Core Dispatch Request in the same Portfolio storage transaction as the facts that require it. A request owns typed reasons, an explicit semantic deduplication key where its request kind supports coalescing, bounded attempt history, and an atomic pending, waiting, leased, completed, or failed lifecycle; completed means the handler durably processed the obligation and does not imply that the underlying domain or provider outcome passed. Core owns request selection, routing, coordination, interruption recovery, and processing through `core.dispatch.startProcessor()`, while Server-owned Portfolio Core Supervision owns exactly one long-lived Portfolio Core Runtime keyed by each Portfolio Registry Entry id rather than `coreStorageNamespace`. Each runtime contains open storage, an opened Core facade, a Core notification publisher closed over the Portfolio id, and the processor handle; scoped authorized borrows count in-flight use for safe drain. In this slice, the Server notification publisher provisionally logs the full Core-safe `{ portfolioId, notification }` value to the console; Agent Run Channels, WebSockets, subscriptions, queues, replay, and query-subscribe recovery are deferred. New registry entries signal supervision immediately, periodic authoritative reconciliation recovers missed signals, durable registration remains successful when first runtime start fails, and degraded runtimes retry with bounded backoff while healthy Portfolios continue. After Server storage migration supervision awaits one complete registry scan/start attempt before HTTP listening; authorized routes resolve access before borrowing and return generic HTTP 503 rather than Selection Required or request-scoped fallback when the runtime is unhealthy. Dispatch-target Core Work Operations become internal, `CoreServices.dispatcher` and dispatcher preflight are removed, and durable requests replace queued/started/finished Delivery Work Dispatch Actions as the source of queued and running Delivery/Slice work.

Processing is at-least-once for interrupted attempts, not exactly-once for external effects. Each successful request admission atomically advances the local coordination revision, applies any waiting-parent reservation, verifies and acquires all exclusive/shared-capacity claims, and creates one numbered attempt with a renewable time-bounded lease in the same storage transaction. Every dispatched Core write is fenced by the current coordination epoch and attempt token, and expired leases may be reclaimed up to a configurable interrupted-attempt limit that defaults to five. A processor-observed handler error fails the request only when the attempt still owns its fence and the request failure plus safe Event/Action commit successfully; fence loss or failure-record storage loss remains an interruption recovered through lease expiry. Handler errors are not generically retried, while a handler may intentionally reschedule a caught expected condition under its own bounded policy. Terminal request failure is atomically paired with a safe Agent Run Event or Delivery/Slice Dispatch Failure Action carrying the request id/type, attempt number, scope, redacted category, and bounded safe summary; persisted attempt history stores the same safe failure boundary and never raw thrown values.

Semantic deduplication coalesces matching pending or waiting scheduler, preparation, and release requests; a matching leased request remains immutable while later triggers create or join one pending successor. Claim admission retains broader-scope-first/FIFO ordering and candidate-snapshotted shared capacity, adds an overall per-Portfolio concurrency cap, and reserves an eligible pending broader exclusive claim that is currently unacquirable while active descendants drain so descendant replenishment cannot starve parent work. Scheduler derivation, child request creation, and scheduler-request completion commit in one short transaction. Model turns resume the same open Agent Run Turn from durable Agent Run Event boundaries, unresolved tool calls become outcome-unknown rather than being blindly repeated, blocked model-turn requests wait across preparation failures for a later successful Agent Run Preparation and complete as no longer applicable when the Agent Run or its target closes, sandbox preparation finds and adopts a deterministic-key sandbox before ensuring creation, sandbox release reschedules until absence is confirmed or its handler policy is exhausted, and external Delivery effects use an operation identity stable across automatic attempts together with provider-supported semantic targets for idempotency or reconciliation; the request id remains correlation when a provider has no idempotency-key facility. Interrupted Run Command Requirements still repeat when their applied checkpoint is absent; manual-versus-automatic command reconciliation remains deferred.

A Portfolio-scoped best-effort Core Dispatch Wake is emitted automatically after a successful request-writing transaction, but it carries no work payload and correctness always comes from adaptive polling of stored requests. The first implementation remains portable through Core storage rather than requiring PostgreSQL `SKIP LOCKED` or `LISTEN/NOTIFY`; Core storage must provide atomic transactions that recover after an owning process dies. The Server's JSON backend remains single-host and satisfies that requirement through an upstream Equipped JSON adapter change with a unique lock-owner token and same-host process-instance identity rather than timeout-only or PID-only lock breaking. The processor stops claiming before shutdown, drains for a grace period, uses handler-boundary abort to stop further Core steps, requeues cleanly interrupted owned attempts, and otherwise relies on lease expiry.

Portfolio Snapshots preserve logical request ids, typed reasons, and bounded attempt history. Restore atomically advances the destination-local coordination epoch, closes imported leased attempts as intentional restore interruptions without consuming their crash-recovery budget, returns those requests to pending, marks incomplete Agent Runs preparation-pending, and ensures preparation requests; preparation adopts and verifies a found imported Sandbox Key or recreates an absent sandbox and resets its sandbox-local applied checkpoints before model turns reactivate. Completed requests are retained for 24 hours by default and pruned in bounded batches, failed requests remain retained in this slice, and a read-only paginated Core query exposes operational lifecycle and history. Consumer-authorized requeue/acknowledgement commands, Server management UI, per-kind concurrency pools, generic attempt timeouts, broad provider cancellation propagation, PostgreSQL-specific optimizations, multi-host JSON, and Run Command Requirement reconciliation are deferred.
