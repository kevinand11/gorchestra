# Source Control Delivery and Slice Branches

For Source Control Project Deliveries, the Delivery Artifact is exactly one Delivery Branch, created lazily from the Delivery's Target Branch when execution first begins rather than when the Delivery is accepted. A Plan Output must specify an immutable Target Branch for each Source Control Project Delivery; the Delivery Branch is created from that Target Branch and merged back into it when the Delivery ships. Each Slice gets a Slice Branch as its Slice Artifact, created lazily from the current Delivery Branch when that Slice first begins, and Gorchestra promotes the Slice Branch into the Delivery Branch through a Slice Review Surface before the Slice is complete. Slice Branches are mandatory in v1 rather than configurable so schedulable Slices can proceed in parallel without sharing mutable branch state, while the Delivery Branch remains the single authoritative in-progress source control artifact for the Delivery. When multiple Slice Branches are ready to merge and no dependency orders them, Gorchestra merges them into the Delivery Branch in deterministic Slice creation/acceptance order; merge conflicts are resolved by retrying the later merge. Delivery Branches and Slice Branches are kept until the Delivery ships or is abandoned; after shipping or abandonment, branch cleanup is determined by consumer or repository policy while Gorchestra history preserves durable evidence such as Agent Run, Action, and commit references.
