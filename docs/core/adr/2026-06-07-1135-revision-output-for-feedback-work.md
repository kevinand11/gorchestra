# Revision Output for feedback work

Feedback-driven revision work uses a human-reviewed Revision Output shape rather than adding or reopening Slices. Opening a Revision Gate allows Gorchestra to fetch Review Surface Feedback and run revision planning work that proposes how to adjust the relevant Slice Artifact or Delivery Artifact. A Revision Output accounts for fetched Feedback with a Revision Disposition, but is not itself a stored Portfolio artifact, does not store Feedback details as authoritative Portfolio data, and does not authorize Gorchestra to post responses back to the Review Surface. If a response to Feedback is needed, a human responds manually on the Review Surface. A Revision Output is accepted or rejected as a whole; if only part of it is acceptable, the human continues negotiation until a new acceptable whole is produced. A single Revision Gate opening may produce multiple rejected Revision Outputs before one is accepted or the gate is closed. Accepting the Revision Output creates a Revision with an Instruction Source and Revision Disposition for Agent Runs against that artifact, and consumes the gate; it does not change the accepted Slice structure. This preserves Delivery immutability while still giving humans a reviewable plan before Gorchestra acts on feedback.
