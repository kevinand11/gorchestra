# Revision Output for feedback work

Feedback-driven revision work uses a human-reviewed Revision Output rather than adding or reopening Slices. Opening a Revision Gate allows Gorchestra to fetch Review Surface Feedback and run revision planning work that proposes how to adjust the relevant Slice Artifact or Delivery Artifact. Accepted and rejected Revision Outputs are stored in Gorchestra history. A Revision Output accounts for fetched Feedback with a human-readable disposition for people viewing the Revision Output in Gorchestra, but does not store Feedback details as authoritative Portfolio data and does not authorize Gorchestra to post responses back to the Review Surface. If a response to Feedback is needed, a human responds manually on the Review Surface. A Revision Output is accepted or rejected as a whole; if only part of it is acceptable, the human continues negotiation until a new acceptable whole is produced. A single Revision Gate opening may produce multiple rejected Revision Outputs before one is accepted or the gate is closed. Accepting the Revision Output authorizes revision Missions against that artifact and consumes the gate; it does not change the accepted Slice structure. This preserves Delivery immutability while still giving humans a reviewable plan before Gorchestra acts on feedback.
