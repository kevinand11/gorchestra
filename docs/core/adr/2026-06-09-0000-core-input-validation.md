# Validate Core Inputs at public boundaries

Core validates every Core Input passed through public Consumer-to-core APIs with Valleyed pipes before core behavior runs, returning an `invalid-input` Result error that carries the PipeError instead of throwing. Command and query APIs use `CoreError`, while construction/import boundaries use narrower error unions such as `OpenCoreError` and `ImportSnapshotError` so their Result types do not promise unrelated domain failures. Valleyed object pipes normalize Core Inputs by stripping unknown fields rather than rejecting them. Port and storage return values are adapter data rather than Core Inputs, so validating those belongs to a separate hardening effort. We chose boundary wrappers over scattered command-body validation so internal core logic can assume typed, normalized values while Consumers get consistent Result-based error handling.
