# Dispatch coordination claims and Delivery work scheduling

Core Dispatch Requests use Dispatch Coordination Claims rather than Agent Run-only serialization keys. Each request may carry multiple claims, and a Consumer may run it only when every exclusive or shared-capacity claim can be acquired; this lets Delivery-level operations exclude all same-Delivery Slice work while sibling Slice operations can run concurrently within the `maxProcessableSliceSlots` capacity snapshotted from the Delivery Work Resolution that emitted them. Among acquirable readied requests, the v1 dispatcher prefers broader parent scopes before descendant scopes, with FIFO as the tie-breaker; blocked requests do not stall unrelated acquirable work.

Delivery work scheduling is split from concrete work: a Delivery Work Scheduler Pass reads current Delivery Context and Delivery Work Resolution, emits concrete Delivery Work Operations, and later commands or completed operations request another scheduler pass. Delivery Work Operation kinds mirror the Delivery Work State or Slice Work State variant they were emitted from. Operation jobs re-read current state before side effects and treat stale derived-state claims as successful no-ops. V1 records generic queued and started Delivery Work Dispatch Actions so schedulers can derive in-transit Delivery/Slice work and avoid duplicate scheduling; the queued Action and Core Dispatch Request are accepted in the same transaction, and started Actions reference their queued Action. Normal operation result Actions reference the started dispatch Action where practical, while stale no-op operations record a generic finish/no-op Action. These Actions do not include lease recovery, and a generic durable Core Dispatch Request outbox remains a later reliability improvement.

V1 uses typed hierarchical claim scopes. Agent Run-related requests use exclusive `[agent-run, agentRunId]`. Delivery Work Scheduler Passes use exclusive `[delivery, deliveryId, scheduler]` so scheduler passes for one Delivery serialize with each other while still allowing Slice work to run. Delivery-level operations use exclusive `[delivery, deliveryId]`. Slice operations use a shared-capacity `[delivery, deliveryId, slice-pool]` claim with snapshotted capacity plus an exclusive `[delivery, deliveryId, slice, sliceId]` claim.
