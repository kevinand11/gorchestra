# Dispatch coordination claims and Delivery work scheduling

Supersession note: [Durable Core Dispatch Requests and Core-owned processing](./2026-07-13-1449-durable-core-dispatch-requests-and-processing.md) supersedes the in-memory Consumer dispatch marker lifecycle, acquirable-only fairness rule, and temporary Delivery Work Dispatch Action reliability model in this ADR while retaining hierarchical Dispatch Coordination Claims and the Delivery scheduler/operation split.

The retained decision is that Core Dispatch Requests carry typed hierarchical Dispatch Coordination Claims rather than Agent Run-only serialization keys. Agent Run requests use exclusive `[agent-run, agentRunId]`; Delivery Work Scheduler Passes use exclusive `[delivery, deliveryId, scheduler]`; Delivery-level operations use exclusive `[delivery, deliveryId]`; and Slice operations combine shared-capacity `[delivery, deliveryId, slice-pool]` with exclusive `[delivery, deliveryId, slice, sliceId]`. A request may run only when all of its claims can be acquired, Delivery parent scopes exclude descendants, and the Slice capacity is snapshotted from the Delivery Work Resolution that emitted the request.

The retained scheduler decision separates Delivery Work Scheduler Passes from concrete Delivery Work Operations. A scheduler pass reads current Delivery Context and local Delivery Work Resolution and emits currently actionable Delivery/Slice operations; provider-backed readiness belongs to Process Delivery Work Operation before external side effects. Operation processing re-reads underlying state, treats stale claims as successful no-ops, records failed provider readiness as Delivery preflight evidence, and requests later scheduling when its handled outcome may make more work actionable. Awaiting-review and failed Work States remain non-actionable until their explicit observation or recovery behavior exists.

The superseded historical implementation had the Consumer acquire claims for readied in-memory requests, preferred broader scopes only after requests were already acquirable, and used FIFO as a tie-breaker. It also recorded generic queued, started, and finished Delivery Work Dispatch Actions so Work State could infer in-transit operations while durable request records and lease recovery were deferred. The superseding ADR moves ownership and durable lifecycle into Core, adds waiting-parent reservation, and makes durable Dispatch Requests the queued/running source of truth.
