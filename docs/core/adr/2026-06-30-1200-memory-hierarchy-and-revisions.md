# Memory hierarchy and revision-backed content

Gorchestra Memory models the Brain as a database-backed Obsidian-like hierarchy: every Memory is note-like, may contain child Memories through an immutable parent relationship, and stores a current revision snapshot for fast reads. Durable edit history lives in separate MemoryRevision records; creating or editing Memory content writes revision history and updates the current snapshot atomically. Memory and Memory Revision are both Portfolio Graph nodes: Memory is the stable note identity, while Memory Revision is the exact content snapshot. Accepted Plan Output memory materialization can create new Memories with initial Memory Revisions or new Memory Revisions for existing Memories, with produced provenance targeting the new Memory when one is created and every materialized Memory Revision. We chose this over flat typed immutable Memories and user-authored Memory Link records because the Brain surface is a note hierarchy first, while authored memory references can live in Memory Revision bodies and exact Core provenance can target immutable Memory Revisions.
